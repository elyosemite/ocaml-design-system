Usar em um produto

Uma fonte, vários destinos. Os tokens moram em src/tokens/; o build gera o CSS para a web e os mesmos valores para TypeScript, SwiftUI, Jetpack Compose e Android. Trocar um token aqui muda todos os produtos na próxima versão.

Instalar
Pelo git, numa versão fixa: pnpm add github:elyosemite/ocaml-design-system#v0.2.0. O prepare roda o build na instalação e gera dist/.
Web (EpistulaMail, OpenBoard, sites)
Importe ocaml-design-system/fonts.css, /tokens.css e /components.css, nessa ordem. Os ícones vêm de /sprite.svg. O tema segue o sistema; force com data-theme="light|dark" no <html>.
Sass
Para usar as mixins de breakpoint ou só parte dos componentes: @use "ocaml-design-system/scss/styles/core/pill".
TypeScript e React Native
import {{ color, dimension }} from "ocaml-design-system/tokens". color.light e color.dark têm os mesmos nomes; dimensões em px.
iOS e macOS (SwiftUI)
Copie dist/platforms/OCamlTokens.swift para o projeto. OCamlColor.text troca sozinho entre claro e escuro; OCamlSpace.space150, OCamlRadius.large.
Android
Compose: dist/platforms/OCamlTokens.kt (OCamlLightColors, OCamlDarkColors, OCamlDimens). Views: android/values/ e values-night/, com @color/ocaml_color_text.
Ferramentas de design
dist/platforms/tokens.json segue o formato DTCG; o valor escuro de cada cor está em $extensions["dev.ocaml.modes"].dark.
Produto novo
Comece pela área de trabalho. Nome e logo do produto entram no .wordmark; a cor de marca é a mesma em todos os produtos.
Versões
Semver: mudança de valor de token é menor (0.x), remoção de classe ou token é maior. O que mudou fica em CHANGELOG.md.
